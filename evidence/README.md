## Boundaries and review notes

The full upstream Evals runner/platform-lite, real providers, Supabase Auth, JWT verification, MCP, PostgREST, Docker and hosted accounts were **not** run. See the main README for precise integration limits. The no-tools control performs no repair; its six passes are the two already-healthy audit-only tasks repeated three times.

The initial binary-discovery implementation found an older Homebrew pg_config. A version acceptance test reproduced that mismatch; commit `8eaa8f6` prefers the installed PostgreSQL 16 and rejects older binaries. All results retained here are from the subsequent clean PostgreSQL 16.15 run, not that earlier environment.

Two deliberate bad write policies exposed false passes during development: anon could INSERT without SELECT visibility, and INSERT permission could apply only to tenant B. Tests failed on both before the probes were corrected; both native and exported graders now reject them. This is why write probes omit RETURNING and cover both tenant values.

The static viewer was opened locally and its unsafe attempt inspected: expected `[1,2]` versus actual `[1,2,3,4]`, green `read_repaired`, red `tenant_isolation`, with the second tenant's synthetic row values displayed. No browser tab or database server was left running. A process inspection after final verification found zero PostgreSQL servers using TwinGuard temporary directories.

Before the final evidence commit, repository-content scans found no absolute user-home paths and no matches for AWS access-key IDs, provider secret-key prefixes, PEM private keys or assigned API-key/password/token values. This is a targeted pattern scan, not a claim of exhaustive secret detection.
